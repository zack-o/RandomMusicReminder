## 使用方式与范围

新建或编辑事项，在底部点击“预览未来安排”。预览和保存使用同一份输入校验，包含尚在输入框内的日期、时间、结束日与间隔；错误时返回对应分区修正。结果为独立全屏清单，显示生成时间、时区和查询范围；可刷新，返回编辑继续修改或保存，预览不自动保存。

查询范围为生成时间之后90天，不含结束时刻；按时间显示最多14条安排、最多14条未安排原因。固定/轮班的提前点分别计数，随机窗口的主提醒与补充合并展示。范围内还有更多安排时提示；没有结果时说明检查规则及90天范围，不将年周期的空结果描述为永不提醒。

| 场景 | 展示行为 |
|---|---|
| 固定时间及秒值 | 显示对应时区的日期与时分秒，准时和不同提前点分别列出 |
| 轮班次日 | 显示真实提示时间及班次开始日、名称和原时刻，结束日期按开始日归属 |
| 日历策略 | 解释原星期/周期、调休补班、自定义工作/休息日及被过滤日期；NONE不受覆盖影响 |
| 已完成/已处理 | 完成状态与原始实例终态不会重新列为将安排；REOPEN及恢复下界参与核对 |
| 停用事项 | 明确当前不安排，不展示假想启用后的结果 |
| 新随机窗口 | 显示可用范围，不执行抽签、不生成或保存种子/选定分钟；补充写“最多1次、重合合并” |
| 既有随机窗口 | 只读复用已有选择，对外仍显示完整范围；只剩固定补充时明确单列 |
| 时区跳时 | 使用与Planner一致的时区解析，固定与轮班均在时刻调整时说明 |
| 未知官方年份 | 提示按原重复规则；按事项日期检查，跨年提前也包含在内 |

预览只针对当前草稿的原始提醒，不含已存在的稍后或TEST。过去时刻不补排，90天之外未查询。随机范围不意味着每分钟都会提示；既有窗口可能已经开始但主提醒仍待触发，因而仍显示完整范围。

这是一份按当前草稿和本机记录计算的快照，不代表系统已经注册提醒或保证准点送达。时间经过、日历或完成状态被其他操作修改后，应刷新；保存时仍按当时状态重新计算。单日换班、未来生效版本等尚未实现的规则不包含在预览中。

## 实现与数据边界

保存和预览共用`SchedulePreparation`准备种子保留、时间方式版本、首次窗口边界、跟踪起点与恢复下界；预览的临时规则id按保存时相同的offset规则匹配已有id，避免编辑后漏掉终态保护。Planner与原因说明共用`ScheduleDateRules`，保留每日/每周的工作日替代、月/年/间隔的交集、轮班相位和班次开始日口径。

`SchedulePreviewRepository`在Room事务中读取单次快照，再在后台计算，不写事件、实例、动作、种子或系统安排。未保存窗口通过首个可用分钟检查范围/边界，不调用随机选择；真实调度默认仍使用原抽签方法。保存并不复用预览的临时身份或范围检查结果。

Room10与JSON7不变，未新增依赖或权限。schema1～10已与本轮修改前基线逐个校验，全部相同。源码快照`build/source-before-schedule-preview-20261029/source.zip`保存662个文件及SHA256基线；源码回退需逐文件核对，避免覆盖其他未提交工作。本轮没有修改设备数据库，也没有新增数据库降级路径。
