## 使用入口与行为

### 四种提醒方式

在事项“基本 → 提醒方式”选择：

| 方式 | 应用行为 |
|---|---|
| 音乐 | 选择音乐并播放；曲目失败可沿用原音乐兜底；不主动请求震动 |
| 仅震动 | 不创建音频播放器、不请求音频焦点、不调用音频兜底；缺节奏缓存时用震动预设 |
| 音乐加震动 | 分别启动音乐与震动；声音失败不把触感参数改成其他方式 |
| 仅通知 | 无声通知，无播放器/马达，不自动打开全屏；通知中仍可停止或稍后 |

旧事项升级后默认“音乐”，需要震动时主动选择。温和/强提醒仍控制提醒强度，与输出方式分开。新无声频道的代码会继承旧频道重要性，保留旧频道，避免默认重开已关闭频道；系统实际展示与用户设置继承仍待设备核验。

震动提供轻点/双脉冲/三连提示，轻/标准/明显强度，以及500～5000毫秒循环间隔。每个脉冲20～160毫秒、相邻至少40毫秒空隙、总占空比不超过35%，每轮另外加入间隔。不支持振幅调节时采用短脉冲，并明确说明强度转为脉冲时长控制；不会不作说明地把弱幅度直接当成全强度。能力依据见[Android官方触感API](https://developer.android.com/develop/ui/views/haptics/haptics-apis)。

停止、稍后、替换、超时或服务销毁会取消本会话马达、计时器与资源；无音频提醒有受时限约束的CPU保持，防止停止计时依赖播放器。试震不抢占正在进行的震动提醒，旧预览停止也不能取消后来开始的提醒。

Android14+无音频提醒采用`systemExempted`前台服务类型，声明其普通权限，使用已有精确提醒资格；不满足条件时保留无声失败通知，不改用音乐。[Android官方说明](https://developer.android.com/about/versions/14/changes/fgs-types-required)明确列出包括纯触感提醒的资格条件。此路径尚未设备运行，不能据声明推断系统一定允许启动。

### 从本机音乐生成节奏

入口：“音乐 → 某首歌的歌曲操作 → 封面、歌词与震动节奏 → 生成或查看震动节奏”。进入生成页会停止音乐试听。

选择片段起点与10～30秒时长，仅解码应用私有音乐副本，不播放、不录音、不联网。按20毫秒能量帧提取起伏，转成有间隔的短脉冲；过静、变化不足、源文件失效或不支持的格式会提示换片段/预设。每首缓存一份最新成功结果，失败或取消保留此前成功缓存；生成有取消检查和20秒处理预算，底层Native阻塞不能只靠这个预算证明可即时中断。

界面显示片段范围、脉冲数和示意图。试震需独立确认，使用标准强度、最多2秒，可手动停止；关闭或后台取消生成/试震。自动化本轮没有点击试震。

这是一份能量变化模板，不是精确节拍识别、音高还原或睡眠判断。音乐加震动目前独立循环，**尚不保证与当前歌曲逐拍同步**。解码支持的PCM输出限16位或float、8k～192k采样率、1～8声道；格式不支持时失败，不伪造成功。格式边界参考[MediaFormat的PCM编码说明](https://developer.android.com/reference/android/media/MediaFormat#KEY_PCM_ENCODING)，实际曲目兼容仍待测试。

### 合并、失败与数据

同刻组分别合并声音/震动需求，各自从请求该通道的事项选曲；多条震动参数采用按实例稳定排序的首个震动事项，通知和提醒页标明来源。只震动事项不会为自己启动声音；若同刻还有音乐事项，声音来自该音乐事项。

缓存缺失、过期、来源变化或不安全时用所选震动预设并显示原因；没有马达或震动失败时保留通知。“已请求震动”不表示系统保证马达实际振动。普通停止不等于事项完成。

Room9只新增五个输出/触感列，保留schema1～8；JSON6读取兼容1～5，保存事项的输出方式、预设、强度、间隔和音乐节奏开关。缓存为本机派生数据，按算法版本和曲目文件身份核对，不进入普通或系统备份；导入后需要重新生成，缺缓存保持原输出方式并用预设，不切成声音。旧版应拒绝JSON6，勿手改版本号。

AI创建草稿接受明确的输出/触感参数，未知枚举拒绝，预览后才能新增；所选批改暂未开放这些字段。模型仍可能误解自然语言，须核对确认页的实际方式；本轮未测试真实供应商。

建议在明确可用的测试设备先无声运行上述用例，再在另外明确授权后核验：

1. 四种方式保存/重开/备份导入后保持；纯震动的稍后、回收恢复及后台启动失败重试不变成音乐。

3. 用户明确选择的私有音乐副本，支持格式的成功生成、长曲起点、截取范围、取消与后台、缓存失效；未经授权不扫描或上传整库。
4. 明确确认后最多2秒试震，手动/后台/离开停止，以及预览不能抢占或取消新的提醒。
5. 熄屏、锁屏、Doze、停止时限、服务被回收及精确提醒资格不足时的无声通知；核对新旧通知频道与既有关闭设置。
6. 音乐提醒原静音WAV播放与错误兜底检查，确保新通道没有破坏既有音乐模式；真实出声仍需单独授权。
