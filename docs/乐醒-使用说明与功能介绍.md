# 乐醒使用说明与功能介绍

适用版本：0.15.0 开发版  
更新日期：2026年10月29日  
适用平台：Android 8.0及以上

乐醒是一款以本地运行为主的事项提醒工具，适合抢票开售、工作待办、会议、缴费、上课、轮班和值班等场景，也可以作为起床提醒使用。

你可以为同一件事设置准时和提前提醒，使用固定时间或随机时间窗，搭配本地音乐、震动或无声通知。需要跟踪待办时，还可以明确记录“完成本次”，保留下一周期的安排。AI为可选功能，需要自行配置第三方服务；关闭AI后，本地提醒、音乐、日历和记录仍可使用。

## 一、先了解主要功能

| 功能 | 可以做什么 |
|---|---|
| 固定时间提醒 | 用时、分、秒设置时刻，支持滚轮和直接输入 |
| 多个提醒点 | 同一事项设置准时、提前几分钟、几小时或几天提醒 |
| 周期提醒 | 单次、每日、每周、每月、每年、每N天，以及轮班 |
| 随机时间窗 | 在指定范围内随机安排一次主提醒，可选择跨午夜 |
| 轮班与白夜轮换 | 自定1～60天周期，逐日设置时刻、休息日和次日提醒 |
| 日期临时调整 | 跳过单日或连续多天，替换当天轮班，按单日或区间恢复，后续周期不移动 |
| 本地音乐 | 导入、试听、筛选，按全库或自选范围随机轮换 |
| 震动与无声通知 | 选择仅震动、音乐加震动或仅通知；支持本机生成片段震动节奏 |
| 待办完成 | 完成某一次发生、取消其后续提示、撤销完成并查看记录 |
| 预览未来安排 | 保存前核对未来90天内的安排与未安排原因 |
| 分类与回收站 | 用标签筛选事项，删除后恢复，或确认后永久删除 |
| AI助手 | 从文字创建草稿、修改所选提醒、解释排程和检查可能冲突 |
| 数据导出 | 导出配置备份，以及响铃、统计、完成操作等CSV记录 |

底部有“提醒、音乐、日历、设置”四个主页面，点击切换。事项编辑器内部可点击分区，也可左右滑动切换。

## 二、第一次使用：先创建一个简单提醒

1. 打开“设置 → 提醒与权限”，检查通知、精确提醒和需要使用的全屏提示权限。按页面提示检查后台限制。
2. 如果想使用自己的歌曲，先到“音乐”页导入一首或多首音乐，并保持曲目启用。
3. 到“提醒”页点击添加按钮，填写事项名称，例如“周会开始”。
4. 在“基本”选择固定时间、设置时刻和提醒方式；在“重复”选择日期与重复规则；在“提醒点”设置准时或提前量。
5. 点击底部“预览未来安排”，核对日期、时间和过滤原因，再返回保存。
6. 回到提醒列表，检查事项开关与下次安排。需要测试时，使用“10 秒后测试当前提醒方式”，核对弹窗后再开始。

测试会使用独立实例，约10秒后触发，最多持续2秒；音乐测试采用较低的播放器音量，不修改系统音量。实际触发时间和音量仍受手机设置影响。测试不会把待办标记为完成。

设置精确到秒不等于保证按秒送达。抢票、开售等重要事项，应先在自己的手机上验证通知、后台与实际提示方式。

## 三、创建与编辑事项

### 1. 基本：这是什么事、何时提醒

- **事项名称**：用于列表和提示中快速识别，例如“演唱会开售”“提交周报”。
- **详细事项**：可选，用来记录准备步骤、地点、网址或其他备注。当前主要以文本保存，不是可逐项勾选的子任务清单。
- **标签**：例如工作、生活、出行、待办，一件事可以有多个标签。
- **时间方式**：选择“固定时间”或“时间窗随机”。
- **提醒方式**：选择音乐、仅震动、音乐加震动或仅通知。
- **记录待办完成**：需要区分“已经停止提示”和“事情已经做完”时开启，默认关闭。
- **启用提醒**：关闭后保留配置，不安排未来提示；已经正在提示的会话请使用“停止提醒”结束。

固定时间可上下滑动小时和分钟，按需打开“设置秒”，也可直接输入。关闭秒列会把秒归零；切换随机时间窗也会将时间调整为整分钟。

### 2. 重复：安排出现在哪些日期

| 类型 | 设置方法与规则 |
|---|---|
| 单次 | 选择指定日期，只安排这一次 |
| 每日 | 从开始日期起每天重复 |
| 每周 | 选择星期，按每周对应日期重复 |
| 每月 | 按开始日期的日号重复；缺少该日时选择跳过或当月最后一天 |
| 每年 | 按开始日期的月日重复；不存在的日期使用所选缺日策略 |
| 每N天 | 按开始日期每隔1～3650个日历日重复 |
| 轮班 | 以开始日为周期第1天，逐日配置，详见下一节 |

周期事项可以设置结束日期，结束日当天仍在范围内。每月/每年的日号始终以原开始日期为准，例如1月31日使用“当月最后一天”后，2月取月末，3月仍回到31日。

目前按公历计算，不支持农历、每月第几个星期几、每N个月或按完成时间重新计算下一次。

### 3. 提醒点：同一件事提前提醒几次

固定时间事项可以添加多个不同提前量，每个提醒点可分别设置提醒强度、持续时长和稍后选项。

例如会议在14:00开始，可设置：

| 提醒点 | 提示时间 |
|---|---|
| 提前1天 | 前一天14:00 |
| 提前30分钟 | 当天13:30 |
| 准时 | 当天14:00 |

跨日提前点仍属于同一次事项。不要为了多个提醒点重复新建多件相同事项。

“温和”和“强提醒”控制提示的醒目程度，与是否发声分开。强提醒能否全屏显示取决于所选输出方式和系统权限；“仅通知”不会自动打开全屏。

## 四、设置轮班、白夜班和休息日

入口：编辑事项 → “重复” → “轮班”。

1. 设置开始日期，这一天就是周期第1天。
2. 设置周期天数，范围为1～60天。
3. 选择已有模板，或逐日编辑。当前提供做二休一、白夜休休、白白夜夜休休；做四休二等可自行配置。
4. 为每一天填写班次名称，设置是否为休息日，以及“当天启用提醒”。
5. 每天最多添加8个不同的时刻；如果提醒发生在该班次的第二天，为该时刻勾选“次日”。
6. 用“预览两个完整周期”检查原周期，再用底部“预览未来安排”核对日历过滤和提前点，最后保存。

“休息日”是班次标记，不等于自动关闭提醒。是否提示由“当天启用提醒”单独决定；休息日也可以设置自己的提醒时间。

例如，一个6天周期可以这样设置：

| 周期日 | 班次 | 提醒时刻 |
|---|---|---|
| 第1天 | 白班 | 08:30 |
| 第2天 | 白班 | 08:30 |
| 第3天 | 夜班 | 19:30，可另加次日08:00 |
| 第4天 | 夜班 | 19:30，可另加次日08:00 |
| 第5天 | 休息 | 关闭 |
| 第6天 | 休息 | 关闭，或按需独立开启 |

第7天重新进入第1天。跨月、跨年不会重置周期；跳过一个被日历过滤的日期，也不会让后面的班次向前移动。

夜班“次日08:00”归属于原夜班开始日，不会被当成第二天新班次。每个轮班时刻都使用已配置的提醒点；开启待办跟踪后，每个时刻分别完成。

### 临时调整某一天

入口：编辑事项 → “重复” → “日期临时调整”。

1. 输入或用日历选择要调整的日期。轮班选的是班次开始日，不是次日下班提醒的日期。
2. 选择“跳过这一天”；如果是轮班，也可选择“替换当天时刻”，编辑临时班次、开关与各时刻。
3. 核对原规则和本次覆盖，点击“加入当前草稿”。
4. 用“预览未来安排”核对，最后保存事项。只加入草稿尚未生效。

最多保存100个调整日期。跳过会取消该事项日期的全部待触发提醒点与稍后，次日和跨日提前也随原日期处理；后续周期不移动，当前正在提示的会话仍需手动停止。跳过不等于完成待办，也不删除已记录的未完成发生。

临时轮班可为原本关闭的休息日设置提醒，但日历过滤仍然生效。编辑原时刻会保留其处理身份；明确新增时刻视为新的发生，已完成/已处理的原时刻不会重响。

要取消单日调整，在该条记录点击“恢复原规则”，确认“恢复到当前草稿”，再保存。只恢复当前规则下的未来时刻，不补过去、旧稍后或已开始的随机窗口，停用状态不变。

### 连续多天暂停或恢复

入口：“日期临时调整 → 连续日期暂停／恢复”。例如请假期间暂停某个工作提醒：

1. 选择“暂停这段日期”，填写开始和结束日期，起止当天都包含。
2. 核对已有临时班次的处理方式。默认保留这些班次；希望它们也暂停时，明确选择“一并替换为跳过”。
3. 点击“核对区间操作”，查看新增、原已跳过、覆盖与保留的数量，以及涉及的临时班次。
4. 点击“确认加入草稿”，返回后预览并保存事项。退出区间页不会自动保存事项。

一次暂停最多100个日历日，合并后调整日期总数也不能超过100；超限时整段不加入，不会只做一部分。这里按日历日计算，不代表每天原本都有提醒。单次事项只允许选择其发生日期。

恢复时选择“恢复区间内跳过”，填写范围再确认。它只清除区间内的跳过设置，保留临时班次和区间外调整；可以选较长区间清理过去的跳过。停用不自动开启，过去、旧稍后和已开始的随机窗口不补响。

如果之前明确覆盖了临时班次，恢复跳过只回到当前原周期，不会找回被覆盖的临时安排。区间按逐日设置保存，不保留独立的请假分组；以后可选择任意区间恢复。

当前还没有自动跳过下一次或“从未来某天开始使用新周期”。直接修改整个周期会重排未来安排，修改前请核对预览。

## 五、设置随机时间窗

适合有弹性的生活或工作提醒。需要固定时点的抢票、开售等事项，请使用固定时间。

例如希望每天08:00～08:10之间随机提醒一次：

1. 在“基本”选择“时间窗随机”。
2. 设置开始08:00、结束08:10，选择每日重复。
3. 保持稍后和固定补充关闭，即只安排一次随机主提醒。
4. 预览范围并保存。

随机窗口使用整分钟，包含开始和结束两端。重复窗口分别抽取，连续两天抽到相同时刻是可能的；已保存的选择不会因为反复打开应用而重新抽取。

- **跨午夜**：例如23:50～次日00:10，勾选“结束在次日”，按开始日判断重复和日历规则。
- **已进入窗口**：默认跳过已开始的窗口。需要使用本次剩余时间时，勾选“若已进入窗口，本次使用剩余时间”，只从下一完整分钟起选择。
- **稍后提醒**：主动开启后，才会产生额外的稍后提示。
- **固定补充**：主动开启后，在窗口末分钟最多补充一次；如果主提醒恰好选中末分钟，会合并。
- **隐藏已选时刻**：影响乐醒的展示，手机系统的“下次闹钟”仍可能显示实际时刻。

保存前的预览显示范围，不执行抽签，也不锁定随机分钟。这个功能不检测睡眠阶段，也不承诺改善起床或漏听情况。当前轮班使用逐日固定时刻，不与随机窗口混用。

## 六、音乐、震动与仅通知

### 1. 四种提醒方式

| 方式 | 应用如何提示 |
|---|---|
| 音乐 | 从所选音乐范围播放，曲目不可用时可使用兜底铃声 |
| 仅震动 | 请求震动，不播放音乐或使用声音兜底 |
| 音乐加震动 | 同时请求音乐和震动 |
| 仅通知 | 显示无声通知，不播放音乐、不请求马达、不自动全屏 |

如果同一时刻有多件事项，应用会合并提示，并分别选择声音和震动来源。因此，一件“仅震动”事项与另一件“音乐”事项同时发生时，仍可能听到来自后者的声音；请查看提示中的来源说明。

### 2. 导入与选择音乐

到“音乐”页，通过文件选择器导入歌曲。乐醒保存应用内副本，不修改原文件。

- 可以搜索、筛选、排序，启用或停用歌曲。
- 事项选择“全部音乐”时使用全局可用曲目；选择“自选音乐”时，仅使用勾选的可用歌曲。
- 曲目按轮次洗牌，一轮内尽量不重复；每次提示期间循环当前歌曲。
- 试听参数可设置时长、起点和应用内音量；离开音乐页或进入后台会停止试听。
- 移除“应用副本”不会删除原音乐文件，但可能影响使用该曲目的自选音乐事项。
- 封面和歌词取决于文件自身的标签与格式，不保证每首都能读取。

“试听”用于检查一首歌；“测试当前提醒方式”用于检查一件事项的输出配置，两者的参数相互独立。当前没有按歌曲内容自动去重。

### 3. 从本机音乐生成震动节奏

入口：音乐页 → 某首歌的“歌曲操作” → “封面、歌词与震动节奏” → “生成或查看震动节奏”。

1. 选择片段起点和10～30秒时长。
2. 生成后查看片段范围、脉冲数和示意图。
3. 需要体验时，独立确认试震；试震最多2秒，可停止。
4. 回到事项编辑器，选择震动相关方式，打开“使用音乐生成的节奏”。

生成在本机完成，不播放音频、不录音、不上传音乐。每首歌保留一份最新成功结果，失败或取消保留此前成功结果；片段过静、变化不足或格式不支持时，请更换片段或使用预设。

生成的是能量变化模板，不是精确节拍或音高还原。音乐加震动目前独立循环，不保证逐拍同步。缺少有效缓存时使用所选震动预设；硬件能力和系统设置会影响实际触感。

## 七、分清停止、收到、完成与停用

| 操作 | 作用 | 是否表示事情做完 |
|---|---|---|
| 停止提醒 | 结束当前提示，保留其他提醒点及后续周期 | 否 |
| 已收到／确认收到 | 对支持补充的随机窗口，结束当前提示并取消本次待触发补充 | 否 |
| 稍后提醒 | 根据配置延后5、10或15分钟，单个原始提醒最多使用3次 | 否 |
| 完成本次 | 明确完成所选的一次发生，取消这次后续提醒点和稍后 | 是，只完成这一次 |
| 停用事项 | 保留配置，暂停未来安排；当前会话仍用停止操作处理 | 否 |
| 移入回收站 | 取消未来安排，保留可恢复的事项配置 | 否 |

例如每日09:00的事项：停止今天的提示，明天仍会提醒；完成今天，只完成今天这一次，明天的周期也仍保留。如果希望整个事项暂停，请关闭启用开关。

### 跟踪待办完成

1. 编辑事项，在“基本”开启“记录待办完成”，默认关闭。
2. 从提醒列表、详情或正在提示的页面，打开完成入口。
3. 选择具体发生，再核对取消范围，确认完成。
4. 到“设置 → 完成记录”查看或撤销。

开启后从本机今天起跟踪可识别的已排程发生，不倒推此前没有留存的待办；停用期间不新增。未完成的旧发生会保留，可从“近期逾期”或“最早逾期”查找。每个选择范围最多显示60次。

同刻有多个事项时只完成所选的一项；轮班同一天08:00与20:00分别完成，完成早上的不会完成晚上的。试响、超时和遗漏均不算完成。

完成记录显示最近1000条操作，可搜索、筛选；CSV最多导出最近10000条。只有最新的完成动作可以撤销，并且需要再次确认。撤销按当前规则恢复未来提示，不补响过去时刻、旧稍后或已开始的随机窗口，停用事项仍保持停用。回收或已移除事项不能撤销完成，但操作快照会保留。

## 八、用预览、日历和标签核对安排

### 1. 保存前预览

点击编辑器底部“预览未来安排”，可查看生成时间之后90天内最多14条安排，以及最多14条未安排原因。

固定提醒的不同提前点分别列出，随机窗口的主提醒和补充合并展示。预览会考虑日历、已完成/已处理记录和恢复时间边界，不包含旧稍后或测试实例，也不列90天之外的安排。

预览显示时区和生成时间，可刷新，返回编辑不会自动保存。草稿、日历、完成状态或时间发生变化后，结果可能改变，保存时会重新计算。

### 2. 日历与节假日

日历可查看近期已安排的时间点，并设置自定义工作日或休息日。自定义覆盖只影响主动选择了相应日历策略的事项。

| 事项的日历策略 | 作用 |
|---|---|
| 不处理节假日 | 完全按原重复规则，不受自定义休／班影响 |
| 跳过官方放假日 | 从原重复日期中排除放假和自定义休息日，不额外补入其他日期 |
| 仅法定工作日 | 每日/每周可按工作日替代原星期选择；月/年/间隔和轮班仍需先符合原周期 |

如果只想“每周五提醒，但遇放假跳过”，使用跳过放假策略；“仅法定工作日”对每周事项会替代原星期选择，含义不同。

当前官方离线假期数据只覆盖2026年。没有自定义覆盖的未知年份，按原重复规则安排并提示，不会自动推算未来调休。跨日提前和轮班次日均按事项／班次开始日判断日历。

### 3. 标签和搜索

事项最多8个标签，每个1～20个字符，会整理首尾空白并去重。提醒页可按标题、详细事项和标签搜索；同时选择多个标签时，只显示同时包含这些标签的事项。

“设置 → 标签管理”可统一改名、合并同名标签或移除标签。操作前会显示影响数量，移除标签不会删除事项。

## 九、删除、恢复与查看记录

删除事项会先移入“设置 → 回收站”。可以查看、恢复，或独立确认后永久删除；清空回收站也需要确认。

恢复保留事项配置，但默认停用。请回提醒页核对，再按需启用；恢复前的时间点、旧稍后和当时已开始的随机窗口不会重新补响。回收站当前采用手动清理。

记录分为三类：

- **响铃历史**：查看提示发生的时间、曲目及停止、稍后、超时等处理结果。
- **完成记录**：查看明确的待办完成与撤销操作，和停止提示分开。
- **数据统计**：本应用使用时长、前台会话和响铃汇总，不代表整台手机的使用情况或任务完成率。

## 十、配置和使用AI助手

入口：“设置 → AI助手 → 管理连接”。AI默认关闭，由你自行选择第三方服务。

### 配置步骤

1. 新增或选择连接档案，填写服务地址、模型名称和自己的API Key。
2. 核对页面显示的实际请求地址，保存配置；保存本身不会联网。
3. 使用测试或任务前，先核对将发送的内容、目标地址和模型，再确认请求。
4. AI返回创建或修改草稿后，核对具体对象、时间和变更，再确认应用。
5. 回到提醒列表检查启用状态与实际安排。新建合并和导入默认不会替你启用所有事项。

服务需兼容应用支持的文字接口；API Key不代表所有地址和模型都可用。连接测试也可能计费，取消本地请求时服务端也可能已经处理并计费。

### 可以用AI做什么

| 任务 | 使用方式 |
|---|---|
| 创建提醒 | 输入自然语言，先生成待确认草稿 |
| 修改所选提醒 | 明确勾选事项，再核对旧值和新值，支持保护性撤销 |
| 解释排程 | 选择事项，解释已有规则与所选排程 |
| 检查提醒冲突 | 查看所选安排可能重叠的情况，再自行决定如何调整 |
| 音乐搭配建议 | 只发送勾选歌曲的元信息，不上传音频 |
| 解释导入问题 | 根据提示说明如何整理或修正待导入内容 |
| 解读近30天汇总 | 按确认页发送匿名汇总，不代表完整任务完成率 |

示例输入：

> 2026年11月1日09:59:55提醒我演唱会开售，使用固定时间。

> 从2026年11月1日开始，按白白夜夜休休循环。白班08:30，夜班19:30，休息日不提醒。

> 每周五17:30提醒提交周报，提前30分钟再提醒一次，并记录待办完成。

AI可能理解错误，草稿必须核对。当前所选批量修改范围比创建草稿窄，还不能批改标签、输出方式或复杂轮班结构。AI不会自动完成待办、永久删除事项或修改系统权限。

密钥按连接保存在本机，不进入普通备份；更改接收地址后需核对对应密钥。普通提醒不依赖AI联网，AI不可用时不影响已保存的本地规则。

## 十一、备份、导出与迁移

入口：“设置 → 导入导出”。完成操作CSV在“设置 → 完成记录”单独导出。

| 内容 | 当前方式与限制 |
|---|---|
| 正常事项、提醒点、标签、单日调整、日历和设置 | 导出核心数据JSON；包含停用事项 |
| 仅应用参数与外观 | 仅导出设置JSON |
| 响铃历史与统计 | 单独导出CSV，不能回填导入 |
| 完成操作 | 完成记录页导出CSV，不能回导完成状态 |
| 回收站事项 | 普通备份不包含；需要导出时先恢复并保持停用 |
| 音乐文件 | 普通备份不打包；目标手机需自行导入对应曲目 |
| 音乐震动节奏缓存 | 不随普通备份迁移，需在目标手机重新生成 |
| API Key和AI连接配置 | 不包含，需要重新配置 |
| 完成状态、跟踪起点、单日操作的本机时间边界、已选随机时刻和系统安排 | 不作为普通配置备份恢复 |

导入时先选择JSON并预览，只合并新增内容，不整库覆盖。相同安排会跳过，改变标签或待办跟踪开关不会绕过判重；自选音乐必须在目标机唯一匹配名称、时长和大小，否则相关事项会被跳过。

新导入事项默认停用；如需恢复原启用状态，明确选择并核对。设置与事项数据分开确认。导入前快照可导出，但再次导入仍采用合并，不能自动删除刚新增的事项，也不能作为完整回滚工具。

换机前请同时保管配置备份、需要留存的CSV和原音乐。清除应用数据或卸载会影响本机私有副本和配置；普通JSON不能恢复全部使用记录。导出文件可能含事项名称、备注和标签，请按个人资料保存。

## 十二、常见问题

**保存了，为什么没有提示？**  
先检查事项是否启用、时间是否已过、重复和结束日期是否正确，再查看预览与日历过滤原因；确认该次是否已完成或处理。然后检查所选方式是否为仅通知、歌曲是否可用，以及通知、精确提醒和后台权限。应用在重启后、首次解锁前目前不保证提示。

**为什么预览是空的？**  
可能事项停用、下一次在90天之外、结束日已过、日期被过滤，或该次已有处理记录。预览不包含旧稍后与测试实例。

**关闭声音后，为什么还会提醒？**  
停止只结束当前提示，不会取消其他提醒点、随机窗口的固定补充或未来周期。按实际需要选择确认收到、完成本次或停用。

**仅震动为什么没有振动，或者同刻仍有声音？**  
先检查手机马达、系统振动设置和事项输出方式。若同刻有其他音乐事项，声音可能来自合并会话中的另一项，请查看来源说明。

**撤销完成后，为什么没有立刻响？**  
撤销只恢复当前规则下仍在未来的提示，不补响过去、旧稍后或已开始的随机窗口；停用也不会被自动开启。

**AI说已经设置，列表却没有新增？**  
AI文字不是保存结果。需要核对并确认应用草稿，再到列表检查；重复或无法匹配自选音乐的事项可能被跳过。

**备份后能恢复所有东西吗？**  
不能。普通JSON是配置备份，历史、完成状态、音乐、Key和派生缓存各有上述边界，当前不是整机或整库迁移。
