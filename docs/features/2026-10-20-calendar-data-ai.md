# 0.5 日历、数据与 AI 规格

本轮拆成日历、数据、AI 三个独立验收部分；不新增依赖，不操作设备，不真实调用收费 API，不提交或推送。只新增可选 AI 的 INTERNET 权限，其他功能继续离线。

## 日历

一套全局自定义日历，月视图、多选日期、休息/工作/恢复默认、备注和来源。用户覆盖优先于官方日期，NONE 策略忽略所有休假；跳过假期只减不增，工作日模式允许补入日期。未知年份的未覆盖日期仍回退原规则，手动编辑少数日期不表示全年已认证。编辑后重排未来提醒，不改历史。Room 3→4 只增加 calendar_overrides 表。

## 数据

带类型和版本的 JSON：设置预设或核心数据（事件/规则/音乐引用/设置/自定义日历）。不含音乐二进制、API Key、AI配置、系统调度实例或历史回填。统计导 CSV。限制文件体积与条目数，严格校验日期和参数。导入先预览，数据只合并、不替换原事件/日期；缺少或歧义音乐引用的事件跳过并提示。新事件默认停用，可明确选择恢复原启用状态。数据合并 Room 事务完成，设置由独立确认按钮原子应用，避免假称跨 Room/DataStore 事务。

## AI

个人自用 BYOK，配置完整 HTTPS Chat Completions 地址、模型、超时、输出上限和可选 JSON 模式；默认关闭，无配置不请求。API Key 用 Keystore 的 AES-GCM 密钥加密，禁止写日志和备份，禁用重定向与明文 HTTP；不硬编码模型或服务。JSON 模式并不保证语义或字段正确，仍校验本地草稿。

文字识别只产生有限任务与日期草稿，显示具体字段，用户确认后合并；不执行任意代码/SQL，不自动认证“官方节假日”。统计只发送用户预览的汇总，不含事件标题/音乐名称，不把停止解释为任务完成。请求可取消，禁止自动重试产生重复费用；不支持图片、语音、Responses 或供应商专有协议。

## 界面

沿用绿 #356859、浅绿 #B8F0D8、背景 #F7FAF7、次文字 #54645D、强调 #755B2B，系统中文无衬线。日历加入底部第四入口；AI、数据与统计历史使用顶栏菜单。月格只用状态色/休或班字样传递日历信息，下方显示所选日期、来源和当天待提醒数量。数据与 AI 页左对齐分区，所有外部输入先预览后确认，不添加无关装饰。

## 验收

本地 JVM 覆盖日历优先级、日期、参数、重复识别及 HTTP 配置校验；实际 JSON 编解码和 Keystore/Compose 增加 Android 测试并仅编译，未运行必须明示。Python 内存 SQLite 验证 1→2→3→4。构建、Lint、APK 与离线静态检查通过后交付，实网、设备与真实音频仍未验证。

协议依据：[OpenAI Chat API](https://developers.openai.com/api/reference/resources/chat)、[结构化输出与 JSON 模式](https://developers.openai.com/api/docs/guides/structured-outputs)。实现仅采用通用 Chat Completions 字段，兼容性需各服务实际验证。
