## 使用入口与行为

编辑事项，在“基本”开启“记录待办完成”，默认关闭，普通闹钟无需开启。开启从本机今天起保存可识别的已排程发生；已有今天的可识别实例补录，后续依计划保存。停用期间不新增，不追溯开启前没有留存的历史待办。未完成实例独立保存，排程超过30天被清理后仍能在逾期选择器处理。

提醒列表、事项详情和正在提示页面可选择“完成本次事项”。先选择具体发生，再确认取消范围；今天及未来、近期逾期、最早逾期三个范围各最多60次，已完成从候选中排除。固定/随机以事项+发生日识别，准时、提前与稍后共享身份；轮班再按稳定时刻key分别识别，夜班次日归班次开始日。

| 操作 | 结果 |
|---|---|
| 完成每日9点事项本次 | 取消这次的提前/准时后续点及稍后，下个周期保留 |
| 完成轮班8点时刻 | 同一天20点与次日时刻各自独立，不被一并完成 |
| 同刻多事项选择其中一项 | 只结束该发生的正在提示部分；其他事项继续，刷新标题、来源、按钮，保留原入口与剩余时限 |
| 完成最后一个正在提示的发生 | 结束会话，响铃历史单列“事项已完成” |
| 停止、确认收到、稍后、超时、遗漏 | 保持原处理语义，不追加待办完成记录；试响不能完成 |

“设置 → 完成记录”展示最近1000条操作，支持搜索、完成/撤销筛选，导出最近最多10000条CSV。记录保存当时标题、发生日和时刻，事项永久删除后仍留操作快照。数字是显示范围内的操作次数，不表示全量待办完成率或提醒送达率。

只有最新DONE动作可撤销，需再次核对。撤销追加REOPEN，按当前配置恢复此发生尚未触发的未来提示，不补过去、旧稍后与已开始的随机窗口；停用保持，当前规则已不覆盖该发生时不新增。回收或已移除事项不能撤销。后续改动会阻止使用旧确认结果，需重新选择。

完成、取消同key排程和会话状态更新在数据库事务内执行，重复点击不重复追加DONE；Planner与排程写入前均核对完成/撤销状态，阻止旧计划复活。动作先后取自增id，避免手机时间回拨改变“最新动作”。确认后的保存与重排不因响铃页退出取消；保存后系统重排失败单独提示核对，记录已保存不等于系统安排成功。

## 数据与兼容

Room10仅新增跟踪开关、本机跟踪边界、排程发生key及两个表：`task_instances`跟随事项永久删除；`task_actions`无事项外键，保留操作快照。旧事项默认关闭。旧非轮班根据baseDate回填key，旧轮班仅在稳定UUID与时刻key可对应时补录，不猜测展示文字。已核对schema1～9与本轮修改前快照完全一致。

JSON7读取兼容1～6，只携带跟踪开关，不携带本机起始边界、实例、完成状态或操作记录；导入目标机从本地今天起跟踪。跟踪开关不参与导入身份判重，不能靠更改开关创建重复提醒；AI版本核对仍比较开关。CSV为留存查看用途，不支持回导完成状态，并沿用公式内容防护。AI只可按明确要求生成开启跟踪的创建草稿，不能自动完成事项。

没有新增依赖或权限。修改前源码快照位于`build/source-before-task-completion-20261028/source.zip`，基线642个文件。源码回退应核对本轮文件后恢复，避免覆盖其他未提交工作；没有提供Room10到9的数据降级，旧APK不能作为升级后数据库的直接回退方案。本轮没有在设备执行升级或改写用户数据库。
